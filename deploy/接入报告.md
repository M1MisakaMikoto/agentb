# AgentB 接入报告（区域平台接入说明）

> 适用范围：本文只描述**本项目（AgentB）**自身的接入方式，不描述上层平台（报告上传系统、AI 研判系统、日常巡查系统、统一门户）的内部实现。
> 目标读者：负责把 AgentB 部署到新区域的技术实施人员。

## 一、系统构成与进程

| 进程 / 服务 | 启动方式 | 作用 | 端口 |
| --- | --- | --- | --- |
| API 实例 | `gunicorn app:app -c gunicorn.conf.py`（Docker 镜像默认） | 会话/对话（SSE 流式）、工作区、计划、设置、RAG 接口 | 容器 8000 |
| API 实例（多实例） | 同一镜像起 3 个实例 | 由 Nginx 一致性哈希路由 | 容器 8000 |
| 路由（多实例模式） | `compose.standalone.yml` / `compose.platform.yml` 内的 `agentb-router` | 一致性哈希 + `/api` 前缀剥离 | 宿主 8152（单机模式） |
| RAG worker | `python -m rag.worker` | 文档入库/删除任务执行 | 无 |
| **上游工具 MCP 服务** | `python -m mcp_servers.upstream_tools.server` | 报告上传、巡查记录、AI 研判四类上游工具（MCP / streamable-http） | 容器 8181 |
| MySQL | 外部或 compose 内置 | 会话/对话主存储 | 3306 |
| Redis（可选） | 外部或 compose 内置 | 消息队列、会话租约、RAG 任务队列 | 6379 |
| SQLite + sqlite-vec | 文件 | RAG 元数据与向量 | 无 |

流式链路：`GET /session/conversations/{conversation_id}/stream?last_seq=&mode=interactive|silent`，
事件类型包含 `thinking_*`、`text_*`、`tool_call`、`tool_res`、`user_input_request`、`state_change`、
`error`、`cancelled`、`done`，以及本项目新增的 **`system_alert`**（系统级告警，如上游工具 MCP 服务不可用）。

## 二、对外接口清单

| 前缀 | 说明 |
| --- | --- |
| `/user` | 用户信息 |
| `/session` | 会话创建/查询/删除、标题生成 |
| `/session/conversations` | 对话创建、查询、取消、级联删除、SSE 流、resume |
| `/workspaces` | 工作区信息、文件列表、文件上传/下载 |
| `/plan` | 计划读取/状态/更新 |
| `/api/settings` | 设置读取与局部更新（敏感字段脱敏） |
| `/rag` | 知识库、分类树、文档上传/检索/读取、入库任务 |
| `/health`、`/health/ready` | 健康检查、就绪检查（`/health` 内含 `mcp` 状态） |
| `/admin/drain` | 实例下线排空 |

> 多实例部署时 Nginx 会剥离 `/api` 前缀再转发；直连单个 API 实例时**不要**带 `/api`。
> 例外：设置接口在代码里的路由前缀本身就带 `/api`（`/api/settings`、`/api/settings/metadata`），直连后端时按该路径访问。
> 鉴权：所有非公开接口需要请求头 `X-User-ID`；多实例写操作还需 `X-AgentB-Affinity-Key`（详见 `deploy/FRONTEND_AFFINITY.md`）。

## 三、依赖与前置条件

- Python 3.12；依赖见 `requirements.txt`（RAG 完整能力见 `requirements-rag.txt`）。
- MySQL 8.x（库/表启动时自动创建）。
- Redis（可选，多实例、消息队列、RAG 队列需要）。
- **LibreOffice（重要）**：用于旧版 `.doc` 读取与 PDF 生成。安装后用以下任一方式让后端找到它：
  - 环境变量 `LIBREOFFICE_PATH` 指向 `soffice`（或 `soffice.exe`，或 `program` 目录）；
  - 把 `soffice` 放进 `PATH`；
  - 使用默认安装路径（`C:\Program Files\LibreOffice\program\soffice.exe`、`/usr/bin/soffice` 等）。
  Docker 镜像已内置 LibreOffice 与排版依赖，无需额外配置。
- pandoc（可选，`PANDOC_PATH`）：生成 DOCX 时的首选转换器。
- WeasyPrint（可选）：PDF 渲染的**备选**路径，需要系统 GTK/Pango 运行库；本机没有时由 LibreOffice 承担 PDF 生成。
- 字体：容器镜像内置 `fonts-noto-cjk`，用于 PDF 中文排版。

## 四、部署方式

### 4.1 Docker Compose（推荐）

1. `cp .env.compose.example .env.compose`，至少设置 `MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。
2. 准备**上游工具 MCP 服务的配置文件**（见第五节），通过 `AGENTB_MCP_UPSTREAM_CONFIG_FILE` 指向它（默认挂载 `WorkBranch/mcp_servers/upstream_tools/config.example.json`，新区域必须替换为真实配置）。
3. 启动：

   ```bash
   docker compose --env-file .env.compose -f compose.yml -f compose.standalone.yml up -d --build
   ```

   平台模式（由上层平台代理转发，不发布宿主端口）：

   ```bash
   docker compose --env-file .env.compose -f compose.yml -f compose.platform.yml up -d --build
   ```

4. 验证：`curl http://127.0.0.1:8152/router-health`、`curl http://127.0.0.1:8152/api/health`。

Compose 里与本项目接入强相关的三个服务：`agentb-1/2/3`（API）、`agentb-rag-worker`、**`agentb-mcp-upstream-tools`**（上游工具 MCP 服务，监听 8181，只在内网暴露）。

### 4.2 Linux 裸机（无 Docker）

1. 安装 Python 3.12、MySQL 8、Redis（可选）、LibreOffice、pandoc（可选）；`pip install -r requirements.txt`，另装 `gunicorn psutil`。
2. 配置 `setting.json`（或 `AGENTB_SETTING_FILE` 指向的文件）与环境变量。
3. 三个进程：

   ```bash
   # 1) API
   cd WorkBranch/backend && $VENV/bin/gunicorn app:app -c gunicorn.conf.py
   # 2) RAG worker
   cd WorkBranch && $VENV/bin/python -m rag.worker
   # 3) 上游工具 MCP 服务
   cd WorkBranch && AGENTB_MCP_HOST=0.0.0.0 AGENTB_MCP_PORT=8181 \
       AGENTB_MCP_UPSTREAM_CONFIG=/etc/agentb/mcp_upstream_tools.json \
       $VENV/bin/python -m mcp_servers.upstream_tools.server
   ```

4. 建议用 systemd 托管三个进程（`Restart=always`）。

### 4.3 卷 / 目录要求（易踩坑）

- **API 与 MCP 服务必须共享同一个工作区目录**：报告工具传的是工作区内的绝对路径（`workspace.base_dir`，容器内 `/app/workspaces`）。Compose 已让 `agentb-mcp-upstream-tools` 也挂载 `agentb-workspaces`。
- `agentb-workspaces`、`agentb-rag-data`、`agentb-rag-docs` 与 Redis AOF 需纳入备份。

## 五、上游工具 MCP 服务配置（新区域必改）

MCP 服务**不读取后端的 settings 服务**，只用自己的配置文件与环境变量：

配置文件默认 `<MCP服务目录>/config.json`，可用 `AGENTB_MCP_UPSTREAM_CONFIG` 指定。字段：

```json
{
    "facility_report": { "api_url": "http://<报告系统>/", "timeout_seconds": 30 },
    "dailypatrol":     { "api_url": "http://<巡查系统>/", "timeout_seconds": 30, "secret_key": "<agent 回写密钥>" },
    "ai_judgment":     { "api_url": "http://<研判系统>/", "timeout_seconds": 30 }
}
```

环境变量覆盖（密钥建议用环境变量注入，不入库）：

| 环境变量 | 覆盖字段 |
| --- | --- |
| `AGENTB_MCP_FACILITY_REPORT_API_URL` / `..._TIMEOUT_SECONDS` | `facility_report.*` |
| `AGENTB_MCP_DAILYPATROL_API_URL` / `..._TIMEOUT_SECONDS` / `AGENTB_MCP_DAILYPATROL_SECRET_KEY` | `dailypatrol.*` |
| `AGENTB_MCP_AI_JUDGMENT_API_URL` / `..._TIMEOUT_SECONDS` | `ai_judgment.*` |
| `AGENTB_MCP_HOST` / `AGENTB_MCP_PORT` | 服务监听地址（默认 `127.0.0.1:8181`） |

配置缺文件、缺段、缺字段时服务**直接报错**，不做静默兜底。

四个 MCP 工具与参数（由服务端 `inputSchema` 自动转译为提示词里的工具说明）：

| 工具 | 必要参数 |
| --- | --- |
| `submit_facility_report` | `reportName`、`facilityId`、`facilityName`、`reportFile`、`regionId` |
| `submit_facility_forecast` | `regionId`、`facilityId`、`predictYear`、`reportFile`（可选：`facilityName`、`predictedHealthScore`、`predictedRiskLevel`、`summary`） |
| `submit_dailypatrol_record` | `title`、`xcdate`、`typeid`、`typename`、`nameid`、`ssname`、`xcunitname`、`dq`、`isdjrw`、`isyhby`、`xcperson`、`xcphone`、`xcunitid`（其余可选） |
| `submit_ai_judgment_issue` | `facilityId`、`facilityName`、`title`、`regionId`（可选 `description`） |

后端侧连接配置（`setting.json` → `agent_tools.mcp.upstream_tools`）：

| 配置项 | 环境变量 | 默认 |
| --- | --- | --- |
| `url` | `AGENTB_MCP_UPSTREAM_TOOLS_URL` | `http://127.0.0.1:8181/mcp`（compose 内为 `http://agentb-mcp-upstream-tools:8181/mcp`） |
| `timeout_seconds` | `AGENTB_MCP_UPSTREAM_TOOLS_TIMEOUT_SECONDS` | 60 |
| `probe_timeout_seconds` | `AGENTB_MCP_UPSTREAM_TOOLS_PROBE_TIMEOUT_SECONDS` | 5（启动探活用的短超时） |

### MCP 可用性语义（重要）

1. 服务**启动探活是后台任务**，不阻塞后端启动；失败只告警（日志 + `/health` 的 `mcp` 字段）。
2. MCP 不可用时，这四个工具**不会出现在模型可见的工具协议里**；提示词会注入 `<service_alert>`，要求 agent 说明“该功能依赖的上游服务不可用”，技能/要求里提到的缺失工具也要如此说明。
3. 调用期失败（运行中掉线）会如实失败，并在日志、tool_event 与会话流的 `system_alert` 段**重复告警**；上游业务错误（例如“用户不存在”）不算服务故障，不会误报。
4. 不做本地兜底、不做工具清单缓存。

## 六、技能（skill）系统

非通用指导（本区域特有的规则、格式要求）以技能形式落盘，agent 通过 `skill` 工具按需读取。

目录约定（根目录由 `agent_tools:skills:dir` / `AGENTB_SKILLS_DIR` 指定，默认 `WorkBranch/skills`，相对路径以 `WorkBranch` 为基准）：

```text
skills/
  region-database-rules/SKILL.md
  report-format/SKILL.md
  <自建技能>/SKILL.md
```

`SKILL.md` 格式：

```markdown
---
name: <技能名，必须与目录名一致>
description: <用途与“什么时候该读”>
---
<技能正文>
```

校验规则（不合法直接报错，不静默跳过）：缺 `name`/`description`、`name` 与目录名不一致、正文为空。

工具契约：`skill:{"operation":"list|read","name":"<list 返回的技能名>"}`；`list` 返回全部技能名与用途，`read` 返回技能全文。

当前内置技能：

| 技能 | 承载内容 |
| --- | --- |
| `region-database-rules` | 本部署的地区表/编码规则（TB_Market.Id、`dq`/`region_id`/`regionId` 同源、禁止用地区名等值匹配） |
| `report-format` | 报告结构模板（标题、基础信息、整体状况、分部位统计表格、处治建议）与表格强制要求 |

**新区域落地**：直接替换/新增 `skills/` 目录内容即可，无需改代码；如需按区域保留多套，用 `AGENTB_SKILLS_DIR` 指向不同目录。

## 九、新区域适配清单（逐项打勾）

1. `setting.json`：`llm.*`（含是否支持视觉）、`workspace.base_dir`、`agent_tools.sql.databases.BTManager` 指向本区域业务库。

3. MCP 服务 `config.json`：三个上游系统的地址、超时、巡查回写密钥（建议密钥走环境变量）。
4. `skills/` 目录：替换为本区域的地区规则与报告格式（`region-database-rules` 至少改表名/地区示例/编码口径）。
5. 报告格式：若本区域报告结构不同，改 `report-format` 技能，无需改代码。
6. 业务库：确认 `TB_Market`、`TO_Org_User`、设施表与 `dq` 语义一致（SQL 工具会按用户区域自动加过滤）。
7. 部署：确认 API 与 MCP 服务共享工作区卷；LibreOffice 可用（`.doc`/PDF）；字体支持中文。

## 十、验收 checklist

1. 健康检查：`GET /health` 返回 `status=ok`，且 `mcp.available=true`（`/health/ready` 返回 200）。
2. 会话链路：创建会话 → 创建对话 → `GET /session/conversations/{id}/stream` 能收到 `text_delta` 与 `done`。
3. 技能链路：提问“列出本部署可用技能”，应看到 `skill` 工具被调用且返回技能清单；再提一个报告类任务，应出现 `skill read report-format`。
4. 报告可信度：一份报告类任务完成后，报告末尾应包含「## 数据来源与工作流程」与「## 结论依据说明」。
5. 知识库口径：分别构造（知识库正常 / 空结果 / 工具错误）三种情况，报告结尾措辞应分别为「基于知识库 / 综合模型知识和知识库 / 基于模型知识」；数据库报错行为保持原样。
6. 上游工具（需 mock 或真实上游）：
   - `submit_facility_report` / `submit_facility_forecast`：先用 `document w` 生成 DOCX，再提交，上游返回成功；
   - `submit_dailypatrol_record`：回写成功（密钥正确）；
   - `submit_ai_judgment_issue`：错误透传（如上游返回扁平型错误结构，message 应原样出现在工具回执里）。
7. 破坏性操作：要求“删除数据库所有表数据”，agent 应直接说明只读限制，不得反复重试或绕过（必要时以文本形式给出替代做法）。
8. 掉线演练：停掉 MCP 服务后重启后端 → 只有告警、服务可正常启动；`/health.mcp.available=false`；四个上游工具不出现在工具协议中；恢复 MCP 后重新启动后端即恢复。
9. 文档能力：`.doc` 读取、`document w` 生成 PDF 各成功一次（验证 LibreOffice 与 `LIBREOFFICE_PATH`）。

## 十一、已知限制与注意事项

1. **视觉能力取决于模型名**：并非所有同名模型都接受图片。实测（DashScope 兼容端点）`deepseek-v4.1-flash` 可读图、`deepseek-v4-flash` 不可；若图片场景失败，优先核对 `llm.model` 是否为官方文档中支持 Vision 的当前版本。
2. **PDF 生成优先 LibreOffice**；没有 LibreOffice 时回落到 WeasyPrint，而 WeasyPrint 在 Windows 需要 GTK/Pango 运行库（Linux/容器镜像已包含）。
3. **`.doc` 转换依赖 LibreOffice 或本机 Word**；`docx2python` 只能读 `.docx`，不能作为 `.doc` 转换方案。
4. MCP 探活为后台任务，首个会话可能早于探活完成（此时工具尚未注册、也无告警）。
5. 工具分发为注册表：新增工具需同时登记到 `ALL_TOOLS`（模型可见的参数说明）与执行器注册表，否则调用会得到“未注册执行器”的明确报错。
6. 后端启动时会自动登记已存在的 workspace 目录，生产环境注意工作区目录规模。
